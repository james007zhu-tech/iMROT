# Working on DCiT OS (for Claude, Codex, Gemini, Grok and people)

Read this before changing anything. Also read README.md and the design doc linked there.

## Non-negotiable rules
1. **Every business record carries an asset.** Orders, inspections, jobs, invoices, movements and events all resolve to ATH codes. A write that cannot say which asset it concerns is wrong.
2. **All writes go through `src/server/*`.** Pages and API routes never call Prisma for writes directly; they call the service layer, which allocates numbers inside the same transaction and appends `AssetEvent`s. Reads for display may use Prisma directly.
3. **Numbers come from `src/lib/numbering*.ts` only.** Never build an ATH/QTTH/… string by hand. Country comes from the creator's employee code; each country counts on its own legal entity, so a country gets its entity (System → Legal entities) before anything is numbered there (`NO_ENTITY_FOR_COUNTRY`).
4. **Asset status changes only through the lifecycle** (`src/lib/lifecycle.ts`). Only ACCEPTANCE leads back to IN_SERVICE.
5. **No raw SQL, no AI-written queries.** Dashboards select from `src/lib/metrics.ts`. The assistant's tools are the only data the model sees.
6. **No hard-coded UI text.** Every label goes through next-intl (`messages/th|zh|en.json`); add keys to all three files.
7. **Customer-facing documents use the Word templates in `templates/word/`** via `src/lib/docx`; never redraw them in HTML.
8. **Money:** original currency + BoC rate + CNY on every amount; VAT separate; WHT never reduces the invoice.
9. **Portal users see only their own customer's data** — filter by `customerId` in every portal query and tool.
10. **UI rules (2026-11-03):** list pages end the title row with "+ New …" (`PageHeader newHref`); frames are navy shades only — orange (`alert`) for alarms/conflicts/required/overdue, red (`fault`) only for fault text and alarm codes; step pages have the app back link top-left; every form starts with `<UploadRecognize>`. Use `src/components/ui.tsx`, not ad-hoc styles.
11. **Design notes never ship.** Wireframe annotations (purple "设计说明") explain the design; pages show only titles, labels, data, buttons, alerts.
12. **Show report names, never template numbers** (`reportsFor` in `src/lib/order-steps.ts`).
13. **Contacts are masked by default** (`src/lib/mask.ts`); full view needs a password re-check and is audited. OPD and legal entities are MD-only.
14. **Services throw stable codes** (`DELIVERY_MISMATCH:…`, `SERIAL_EXISTS:…`); pages translate `err_<CODE>` from `messages/*.json`. Server actions must not close over translators (`t`, `u`) — Next cannot serialise them.
15. **Side menu (2026-11-07):** white, icon + four-character Chinese labels; Latin text in Helvetica, Thai Sarabun, Chinese Noto Sans SC. Customer documents: see rule 18.
16. **Drafts keep their number:** "save draft" on INTH / RPTH / PMTH / DNTH updates the same open document; never open a second number for the same unfinished work. A draft registers nothing (no Document, no event, no status change) until it is saved for real.
17. **Signature and stamp blocks** sit at the foot of the page (floating table anchored to the bottom margin), never right after the body text; applies to every template that is signed (rule 2026-11-08). scripts/templates/anchor_signature_bottom.py re-applies it.
18. **Print templates (2026-11-08):** fonts Helvetica for Western text (English, numbers, codes — Arial / Liberation Sans where Helvetica is absent), Sarabun for Thai, Noto Sans SC for Chinese (DCiT System Reference, updated 2026-11-08; `docs/brand/DCiT_System_Reference.docx`); never join items with " · " in body text or value cells — one item per line; table headers are always two lines, English above Thai, in every column; TITH and RCTH print as original + copy; every signature slot accepts an e-signature.
19. **ETH employee file (2026-11-08):** the MD sees the list and edits everything; every other person sees only their own file (no salary) and may edit their own contacts. Contacts and salary amounts are masked until the password is re-entered (`grantReveal` keyed by the ETH code); every salary add and every reveal is audited. `SalaryRecord` rows are the accountant's payroll basis (gross structure, SSO base/rates, PVD, declared tax deductions, estimated withholding) — statutory values in `src/lib/payroll.ts` are defaults copied onto each row, never recomputed over history. Pages with many server actions keep them in a sibling `actions.ts` (`"use server"`), bound only to the record code — production builds otherwise serialise component-scope helpers into the bound arguments.
20. **Finance and purchasing templates (2026-11-08):** 20 Tax Invoice (TITH), 21 Invoice (IVTH), 22 Receipt (RCTH), 23 Statement (BLTH), 24 Request for Quotation (PRTH), 25 Purchase Order (POTH), 26 Goods Receipt (IBTH), 27 Stock Issue (OBTH) are generated by `scripts/templates/build_finance_templates.py` from the approved mockups — edit the script, not the .docx. TITH and RCTH are two-page files (original + copy) sharing one set of placeholders. Line items use `[[L_*]]` placeholders on one template row; `src/lib/docx/fill.ts` repeats the row per line. Amounts in words come from `src/lib/amount-words.ts` (Thai + English). The invoice's withholding line uses `WHT_SERVICE_RATE` (3 % hire of work, confirmed 2026-11-08); SSO defaults in `src/lib/payroll.ts` are the 2026–2028 regulation (5 %/5 %, 1,650–17,500).

21. **Form ⊇ report (朱总 2026-11-08):** every web form holds the full record; the printed Word/PDF report is a subset chosen for its reader. Internal fields (INTH parts and quantities, engineer traceability, costs, margin, approvals, QR/scan features, audit) live only on the form and never on the customer-facing report. Add fields to the form first; add them to a template only when the reader needs them.
## Before a PR
```bash
npm run typecheck && npm test && npm run smoke:mem   # no DB needed
python3 scripts/dev/check-keys.py                   # every t("key") exists in th/zh/en
npm run smoke                                       # with a database
```
Branches: `feat/<module>-<topic>` → PR to `main`. Keep PRs under ~400 lines; one module per PR.

## Where things are
- `prisma/schema.prisma` — data model (comments explain each model)
- `src/server/` — alm (assets/events), slm (orders), slm-docs (INTH/RPTH/ERTH/acceptance/quote), scm, purchasing (PRTH/POTH), srm (合作维修 partner repair, payables), to (invoices/payments/statements), reports (templates), ai (assistant, dashboards), models (product knowledge), auth
- `src/app/(app)/` — staff pages; `src/app/portal/` — customer portal; `src/app/api/` — JSON routes
- `src/components/` — shared UI (badges, charts, assistant, dashboard builder)
- `scripts/smoke.ts` — the ten-step end-to-end test; `scripts/dev/` — in-memory harness

## Style
TypeScript strict, server components by default, `"use client"` only for interaction. Tailwind v4 with DCiT tokens (`bg-navy`, `bg-blue`). Mobile first for the portal. Short files, plain names, comments say *why*.
22. **INTH needs (flow step 3, 2026-11-08):** the inspection form carries "parts and labour needed" rows (`Inspection.needs`, internal — never on the 08 report). Saving for real runs the stock check (`checkNeedsStock`) and `autoInquiryForOrder` raises one PRTH for the short parts unless the order already has an OPEN/COMPARED inquiry; the quote page pre-fills its lines from the needs (part cost = last purchase price). `inquiryLinesFromOrder` prefers quote lines and falls back to INTH needs.
23. **Customer files and closing (2026-11-08):** uploads on a service order are classified INQUIRY / PO / MESSAGE (`RECOGNIZE.service.accept`); the customer page lists every INQUIRY file as "historical inquiries". A DNTH may archive the customer's own delivery note (`DeliveryNote.attachments`, kind CUSTOMER_DN, optional). Settlement no longer closes an order: the person presses "项目完成" (INVOICED → CLOSED) on the QTTH.
24. **TITH void and numbering (2026-11-08):** a tax invoice is voided only through `requestTaxInvoiceVoid` → MD `decideTaxInvoiceVoid`; a TITH with payments is never voided (credit note instead); approval keeps the number, cancels its unpaid IVTH (`Invoice.cancelledAt`, excluded from receivables, payments refused) and lets the order take a new TITH + IVTH. BLTH has a detail page at `/statements/[no]`. QTTH uses a 3-digit daily serial (2-digit numbers issued earlier still parse).
25. **เล่มที่ (2026-11-08):** every TITH gets `seq` / `bookNo` / `bookSeq` at issue — one running sequence per legal entity, books of `LegalEntity.taxInvoiceBookSize` (default 50); a voided tax invoice keeps its place. The DBD lookup is to go through the official BDEX service (docs/dbd-bdex-application.md), credentials in `DBD_API_URL` / `DBD_API_KEY`.
26. **合作维修 / partner repair (flow v4, MD 2026-11-08 — `src/server/srm.ts`, rules in `src/lib/srm.ts`):** a 合作维修 order is `mode PARTNER_REPAIR` (rule 28) — picked at creation, or a REPAIR order is closed and reopened as one after its INTH (`reopenAsPartner`); there is no in-house/partner switch on an order. **The partner never meets the customer:** there is no direct delivery; we carry the machine both ways; PRTH / POTH / 外送 / 返回 documents carry no customer name, plant, PO or QTTH (`partnerSafe` in reports.ts — probe asserts it on the rendered files). Partner PRTH = `kind SUBCONTRACT`, one line per machine; quotes carry `warrantyDays` + `solution`; the selected price is the machine's cost on the QTTH (`partnerCostByAsset` / `spreadPartnerCost`). Margin floor **33 %** for partner orders, 50 % for repair (per mode, rule 28). **Warranty back-to-back:** a partner quote shorter than the customer's `warrantyDays` cannot be selected; the POTH must carry exactly the customer's days. The machine goes out on an **OBTH of kind `SUBCONTRACT_OUT`** (template 28 外送维修单) and comes back on an **IBTH of kind `SUBCONTRACT_RETURN`** (template 29, `refNo` = the OBTH, accessories checked) — no new prefix, parts stock untouched. Progress = `SubcontractMilestone` (internal only, never portal). A POTH change with more cost or a later date needs `customerConsent` (`revisePurchaseOrder`, version +1, cost flows into the margin). Our retest (`recordRetest`) must pass before a DNTH; a fail sends it back under warranty. Acceptance for partner orders needs INTH · POTH · OBTH · IBTH · retest passed · ERTH · DNTH (no RPTH). Payables: `SupplierInvoice` only after the retest passed, never above the POTH; due date monthly = month end + 15 days for Thai partners (default), per order otherwise; WHT 3 % on a Thai partner's repair; paying issues a PVTH (MD/finance). `SupplierRating` 1–5 ×4 ranks `recommendPartners`. Probe: `scripts/dev/probe-partner-repair.ts`.
27. **Service templates (2026-11-08):** 04 Service Proposal (报价建议书), 06 Order Confirmation, 12 Service Completion and 13 Customer Acceptance — all under the QTTH — are generated by `scripts/templates/build_service_templates.py` in the same print system as rule 20 (footer V2.0); edit the script, not the .docx. Their fields come from `serviceFields` in `src/server/reports.ts`: equipment rows `[[L_EQ_*]]`, priced lines `[[L_*]]`, deliverables `[[L_DV_*]]`; report names instead of template numbers; the acceptance decision as ☒/☐ boxes. Every download is rendered fresh in its own folder (`renderDocument` → `cleanup`), PDF conversions run one at a time on a private LibreOffice profile (`convertToPdf`), and files are named number + report (`reportFileName`), never the bare number.
28. **业务模式 (朱总 2026-11-09, mockup `docs/mockups/business-modes-v0.1.html`):** every order is created in one of six modes — REPAIR 维修, PARTNER_REPAIR 合作维修, MAINTENANCE 维保 (kind MAINTENANCE / OVERHAUL / CONTRACT as sub-type), AUTOMATION_PROJECT 自动化项目, DOMESTIC_TRADE 国内贸易, INTERNATIONAL_TRADE 国际贸易 — picked first on the new-order page and **never changed** (`ServiceOrder.mode`). The mode decides the documents, the inquiry/quote route and the margin floor: 50 / 33 / 50 / 20 / 20 / 10 % by default (`DEFAULT_MARGIN_FLOOR` in `src/lib/modes.ts`), the MD changes them on /admin (`ModeRule`, read with `marginFloor(mode)` in `src/server/modes.ts`). A REPAIR order that needs a partner is **closed and reopened** as PARTNER_REPAIR (`reopenAsPartner`: before the quote went out; machines, INTH, ERTH, customer files, contact and reference move to the new order; reason required; `transferredFromId` links them). Trade orders carry SKUs only, no ATH (the one exception to rule 1): the customer's inquiry is `ServiceOrder.requestLines`, shortages raise a PRTH at creation (`autoInquiryForOrder`), the quote starts from the lines, the steps are quote → customer PO → OBTH → DNTH, and **signing the last DNTH accepts and locks the order** (`signDelivery`); the QTTH renders as 30 Quotation / 31 Order Confirmation (SKU column, no equipment, `scripts/templates/build_service_templates.py`); `scripts/dev/probe-trade.ts` runs the chain. `OPEN_MODES` lists the modes that can be opened; automation projects and international trade wait for their flow. `scripts/dev/backfill.ts` (run after every `db push`) gives old orders the mode their kind implies.
29. **调薪通知单 (MD 2026-11-09):** the last step of a salary increase is a STRICTLY CONFIDENTIAL thank-you letter in Thai, English and Chinese — template 32 (`scripts/templates/build_hr_letters.py`, wording tied to the Employee Handbook: pay follows lasting contribution / responsibility / growth, "only contribution counts", values, 5S, confidentiality). `src/server/salary-letter.ts` fills it from the salary record and the one before it (old → new base, +amount, +%), effective date, first payday = the 5th of the next month moved back over weekends and fixed Thai bank holidays (`payday`), Thai dates in the Buddhist era. The personal greeting, title and thanks live in `SalaryRecord.letter`. MD only (page card `#letter`, `/api/people/[code]/salary/[id]/letter`), every edit and render audited; a first salary or a decrease gets no letter. `scripts/dev/make-salary-letter.ts` renders one from the command line; probe `scripts/dev/probe-salary-letter.ts`.
