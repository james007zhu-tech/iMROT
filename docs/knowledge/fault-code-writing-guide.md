# 故障代码宽表规范（给 Grok）

版本 1.0 · 2026-11-10 · 朱总定：故障代码由 Grok 离线整理，直接导入 DCiT OS。
配套示例：`docs/knowledge/fault-code-wide-template.csv`（3 行 ACS880，三种语言都写全了）。

导入后的代码先是**待审核**，由朱总或经理在「故障代码库」里审核、设为对外、发布，然后才出现在对外查询网站 `/faults` 上。
所以这份规范管的是两件事：**表格格式对不对**，**对外文字能不能直接给客户看**。

---

## 1. 交付和导入

**文件**
- 一个系列一个文件，文件名：`品牌_系列_YYYYMMDD.csv`，例 `ABB_ACS880_20261110.csv`。
- CSV，UTF-8 编码，逗号分隔。第一行是表头，列名和顺序照抄示例文件，一列不能少。
- 一行一个代码。一个代码只出现一次。
- 列表类字段（原因、检查步骤、联系前准备、相关代码、关键词）一项一句，项与项之间用 ` | ` 分隔，即空格、竖线、空格。
- 单元格里有逗号、换行或双引号时，整格用英文双引号包起来，格内的双引号写两遍。用 Python `csv` 模块写出就不会错。
- 不要 Excel 公式，不要合并单元格，不要在表头上方加说明行。空着的格子就留空。
- 代码按文本写，保留前导零和大小写：`0001`、`A2B3`、`F30001`。

**导入（在 Mac mini 上，项目目录下）**
1. 把 CSV 放进 `.dev-ops/kb-inbox/`，一次可以放多个文件。
2. 新建一个空文件 `.dev-ops/kb-check`。约 10 秒后读 `.dev-ops/kb-check.out`：只检查，不写数据库。
3. 报告里出现 `✗ BLOCKING` 的行不会被导入。改好文件，重复第 2 步，直到报告最后一行是 `no blocking issues`。
4. 新建一个空文件 `.dev-ops/kb-import`。读 `.dev-ops/kb-import.out`。导入完的文件会自动移到 `kb-inbox/done/`。
5. 告诉朱总：哪个系列、多少条，有哪些 `note` 级提示需要人看。

本机有代码和数据库时也可以直接运行：`npm run kb:import -- 文件或文件夹`，只检查；加 `--commit` 导入。

**导入规则**
- 系统里没有的品牌和系列会自动建立，类别默认为变频器。已有系列只补空白的资料，不改人写过的。
- 系统里**已审核**的代码不会被覆盖，报告里显示为 `APPROVED_NOT_OVERWRITTEN`。要更新已审核的代码，先请朱总在系统里把它退回，再导入。
- 待审核或草稿状态的同号代码会被新文件更新。

## 2. 三类文字，绝不混放

| 类别 | 列 | 谁能看到 |
| --- | --- | --- |
| 我们自己的话 | `title_*` `meaning_*` `causes_*` `checks_*` `remedy_*` `safety_*` `prepare_*` `keywords` | 客户，发布后公开 |
| 原厂手册原文及译文 | `manual_*` | 只在 DCiT OS 内部，永不公开，涉及版权 |
| 内部资料 | `internal_notes` `common_parts` `check_status` | 只在 DCiT OS 内部 |

- 手册的英文原句**逐字**放进 `manual_meaning_en` 和 `manual_actions_en`，中文和泰文译文放进对应的 `manual_*_zh`、`manual_*_th`。
- 对外列必须是**重新写的话**，不是手册句子的翻译。参数号、数值、部件名称可以引用，句子要自己组织。
- 导入时会比对：对外列和手册列有连续 8 个英文单词，或连续 16 个中文或泰文字符相同，这一行就不导入，报告为 `COPIED_FROM_MANUAL`。

## 3. 列说明

示例文件就是标准，下面说明每一列。必填列缺了，整个文件不能导入。

| 列 | 必填 | 内容 |
| --- | --- | --- |
| `brand` | 是 | 品牌，和系统里一致：`ABB`、`SIEMENS` |
| `series` | 是 | 系列代号：`ACS880`、`S120` |
| `code` | 是 | 故障代码，原样照抄 |
| `kind` | 是 | `FAULT` 故障，变频器跳闸停机 · `WARNING` 警告，继续运行 · `EVENT` 事件，只记录 · `INFO` 提示 |
| `must_stop` | | 见第 5 节。空着等于 `UNVERIFIED` |
| `applies_to` | | 适用的固件或产品范围：`ACS880 primary control program` |
| `related` | | 同系列的相关代码，列表，例子见表下 |
| `keywords` | | 人们会搜的其他叫法，三种语言放在一格，列表，例子见表下。不要重复标题 |
| `title_zh` `title_en` `title_th` | 是 | 名称，三种语言都要 |
| `meaning_*` | | 含义 |
| `causes_*` | | 常见原因，列表 |
| `checks_*` | | 检查步骤，列表 |
| `remedy_*` | | 复位与处理 |
| `safety_*` | | 安全提示 |
| `prepare_*` | | 联系 DCiT 前请准备，列表 |
| `manual_meaning_en` `manual_actions_en` | | 手册原文，逐字复制 |
| `manual_meaning_zh` `manual_actions_zh` `manual_meaning_th` `manual_actions_th` | | 手册原文的译文 |
| `source_title` | | 手册名称，不含版本：`ACS880 primary control program firmware manual` |
| `source_doc_id` | | 文档号：`3AUA0000085967` |
| `source_revision` | | 版本：`V` |
| `source_date` | | 文档日期，`YYYY-MM-DD` |
| `source_page` | | 这个代码在 PDF 里的页码，只写数字：`519` |
| `source_url` | | 手册的官方下载地址 |
| `source_sha256` | | 手册 PDF 文件的 SHA-256，用来确认是哪一份文件 |
| `internal_notes` | | 给内部的话：核对情况、疑点、经验 |
| `common_parts` | | 常用备件，只写确认过的，不推测 |
| `check_status` | | 来源核对状态：`已核实`、`待核实` |

列表的写法，以 2310 为例：

```
related         2330 | 2340
keywords        过流 | OC | over current | โอเวอร์เคอร์เรนต์
causes_zh       电机或电机电缆绝缘损坏、相间短路或对地短路 | 加速时间太短，或负载在运行中突然卡住 | …
prepare_zh      完整代码和辅助码 | 故障发生在加速、减速还是恒速 | 最近改过什么：参数、电机、电缆或负载
```

页面会自动用 `source_*` 显示出处，例如「出处：ACS880 primary control program firmware manual · Rev V · 第 519 页」，所以对外文字里不要再写页码。

## 4. 措辞规范

### 总则
1. 写给现场的人看：维修工、电工、设备主管。短句，一句一个意思。
2. 先说发生了什么，再说怎么查。不讲原理课。
3. 用我们自己的话。不确定的不写成事实，没有依据的不写。
4. 三种语言意思一致，**列表条数一致**，不必逐字对应。
5. 对外文字里不写：页码或 PDF 页码，「原文」「手册措施」之类的字样，「联系原厂/代理/ABB 代表」（页面自带联系 DCiT 的按钮），价格，客户名称，购买渠道，品牌比较。不承诺「一定」「保证」「彻底解决」。
6. 不用 ①② 圈号，不用 Markdown、表情符号、感叹号。

### 逐个字段

**title 名称**：名词短语，说是什么。中文不超过 16 个字，英文、泰文不超过 50 个字符。不带代码，不加括号注释，三种语言分列写。
- 好：`过电流` / `Overcurrent` / `กระแสเกิน`
- 不好：`过电流（Overcurrent）`、`2310 过电流`

**meaning 含义**：1–2 句。说清楚变频器检测到了什么，做了什么反应：跳闸停机、报警但继续运行，还是只记录。中文不超过 80 个字，英文、泰文不超过 260 个字符。

**causes 常见原因**：2–6 条，按现场常见程度排序。每条一个原因，中文不超过 40 个字。写现场看得到、查得到的原因，例如「电缆受潮」「加速时间太短」；不写「内部错误」之类的空话。

**checks 检查步骤**：3–8 条，按「先安全、先简单、先外后内」排序。
- 每条以动词开头，只做一个动作，中文不超过 40 个字。
- 需要断电的，写「断电并等待放电后」。
- 需要看或改参数的，写参数号，例如「参数 31.11」。
- 最后一条不写「联系厂家」。

**remedy 复位与处理**：怎么清除，1–2 句。从这几种里选一种说清楚：原因消失后自动清除；排除原因后复位，写明复位方式；需要重启控制单元；更换部件后才能清除。反复出现时可以加一句下一步怎么办。

**safety 安全提示**：检查步骤涉及断电、测量、开盖或靠近转动部件时必须写，否则报 `SAFETY_MISSING`。用下面的标准句，等待时间按该系列手册改：
- 中文：变频器断电后直流母线仍有危险电压。开盖前至少等待 5 分钟，并用万用表确认直流母线电压已降到安全值。
- English: The DC link stays at a dangerous voltage after power-off. Wait at least 5 minutes and confirm with a meter that the DC voltage is safe before opening covers.
- ไทย: หลังตัดไฟ บัส DC ยังมีแรงดันอันตราย รออย่างน้อย 5 นาที และวัดยืนยันว่าแรงดัน DC ปลอดภัยก่อนเปิดฝา

**prepare 联系前请准备**：客户打电话前该准备的信息，2–4 条，例如：完整代码和辅助码；发生时设备在做什么；最近改过什么；铭牌照片。写成名词短语，不写成问句。

### 三种语言
- **中文**：简体。数字用阿拉伯数字，数字和单位之间空一格：`5 分钟`、`400 V`。
- **English**：plain international English, short sentences; checks start with a verb: "Measure…", "Check…", "Note…".
- **ไทย**：ภาษาช่างที่ใช้ในโรงงาน สุภาพแต่ไม่เป็นทางการเกินไป ใช้คำทับศัพท์ที่ช่างไทยใช้จริง เช่น อินเวอร์เตอร์ เอ็นโคเดอร์ พารามิเตอร์ ไม่แปลชื่อพารามิเตอร์ ใช้ตัวเลขอารบิก
- 中文列里不能有泰文，泰文列里不能有中文，英文列里不能有中文和泰文。否则报 `WRONG_LANG`，这一行不导入。中文和泰文列里可以有英文缩写和型号：IGBT、PLC、DC。

## 5. 是否必须停机 `must_stop`

| 值 | 意思 | 什么时候填 |
| --- | --- | --- |
| `YES` | 原因查清前不能继续运行 | 手册明确要求，或 DCiT 工程师确认过 |
| `NO` | 可以继续运行，安排检查 | 手册明确说明，或 DCiT 工程师确认过 |
| `UNVERIFIED` | 没有依据 | 其他所有情况 |

没有依据就填 `UNVERIFIED`。页面上显示「待核实」，**绝不显示为「不必停机」**。依据写进 `internal_notes`。

## 8. 导入检查代码

`✗ BLOCKING` 的行不导入，其余为提示，导入后由审核人处理。

| 代码 | 级别 | 意思 |
| --- | --- | --- |
| `NO_CODE` | 阻止 | 没有代码 |
| `NO_TITLE` | 阻止 | 三种语言都没有名称 |
| `COPIED_FROM_MANUAL` | 阻止 | 对外文字抄了手册原文 |
| `WRONG_LANG` | 阻止 | 某语言的列里出现了别的语言文字 |
| `DUPLICATE_IN_FILE` | 阻止 | 文件里同一个代码出现两次 |
| `MISSING_LANG` | 提示 | 缺某种语言的名称 |
| `TITLE_TOO_LONG` `TOO_LONG` | 提示 | 名称、含义或列表项太长 |
| `TITLE_HAS_CODE` | 提示 | 名称里带了代码 |
| `PAGE_REF` | 提示 | 对外文字里有页码 |
| `MANUAL_WORDS` | 提示 | 对外文字里有「原文」「手册措施」等字样 |
| `CONTACT_VENDOR` | 提示 | 叫用户联系原厂或代理 |
| `CIRCLED_NUMBERS` | 提示 | 用了 ①② 圈号 |
| `LIST_SIZE` | 提示 | 原因超过 6 条，或检查步骤超过 8 条 |
| `LIST_MISMATCH` | 提示 | 三种语言的条目数不一致 |
| `SAFETY_MISSING` | 提示 | 检查步骤涉及断电、测量或开盖，但没写安全提示 |
| `MUST_STOP_UNVERIFIED` | 提示 | 是否停机待核实 |
| `CODE_PATTERN` | 提示 | 代码不符合系列的编码规则 |
| `APPROVED_NOT_OVERWRITTEN` | 提示 | 系统里已审核，未覆盖 |

目标：交付的文件**没有阻止项，提示项尽量为 0**；`MUST_STOP_UNVERIFIED` 和 `CODE_PATTERN` 例外，这两项如实保留。

## 9. 交付前自检

- [ ] 表头和示例文件完全一样，45 列
- [ ] 一个系列一个文件，文件名 `品牌_系列_YYYYMMDD.csv`，UTF-8
- [ ] 每行三种语言的名称都有
- [ ] 对外文字是自己写的；手册原句只在 `manual_*` 列
- [ ] 对外文字里没有页码、「原文」、圈号、「联系原厂」
- [ ] 三种语言的原因、检查步骤条数一致
- [ ] 有断电或测量步骤的行都写了安全提示
- [ ] `must_stop` 没有依据的都是 `UNVERIFIED`
- [ ] `source_*` 填了手册名称、文档号、版本、日期、页码、链接、SHA-256
- [ ] `kb-check.out` 最后一行是 `no blocking issues`
